**Мова:** [English](../../../lab/README.md) · Українська · [Русский](../../ru/lab/README.md)

## Окремий локальний користувач

`run-local-user-lab.sh` працює з уже створеним користувачем Ubuntu `ac-shell-test` з **порожньою конфігурацією** та готовими системними пакетами. Відмовляється запускатися для вже налаштованого облікового запису, не змінює login shell хоста і не використовує APT на хості.

```sh
sh lab/run-local-user-lab.sh
```

## Чиста Ubuntu 24.04 у QEMU/KVM

Потрібні `qemu-system-x86_64`, `qemu-img`, `cloud-localds`, SSH, curl, KVM, щонайменше приблизно 1,5 GiB MemAvailable і 10 GiB вільного диска (перевіряються скриптом). Скрипт хоста працює лише з `/var/lib/ac-shell-lab` і портом `127.0.0.1:22224`; він **не видаляє диски й не завершує чужі VM**. Не використовуйте, якщо ці ресурси вже зайняті іншою лабораторією.

```sh
sudo install -d -m 0700 -o "$(id -un)" -g "$(id -gn)" /var/lib/ac-shell-lab
sh lab/ac-shell-vm-lab.sh prepare
sh lab/ac-shell-vm-lab.sh start
sh lab/ac-shell-vm-lab.sh test
sh lab/ac-shell-vm-lab.sh status
```

Для коректного завершення роботи: `sh lab/ac-shell-vm-lab.sh stop`. Вимкнення асинхронне; перевіряйте `status`. **Автоматичного очищення немає**. Видалення дисків та образів — окрема свідома адміністративна дія.

Сценарій перевіряє опублікований Canonical `SHA256SUMS`, **не** GPG-підпис цього файлу; перевірка підписаного джерела запланована. Приватний ключ SSH лабораторії залишається в `/var/lib/ac-shell-lab` і ніколи не передається до Git.

Перший SSH-вхід може завершитися невдачею, поки працює cloud-init. Дія `test` спеціально очікує завершення cloud-init перед встановленням.
