# Встановлення та експлуатація

**Мова:** [English](../../INSTALL.md) · Українська · [Русский](../ru/INSTALL.md)

## Передумови

- Ubuntu 22.04, 24.04 або 26.04. Повне встановлення з нуля перевірено лише на Ubuntu 24.04.
- Запускайте від **цільового користувача без root**. Для відсутніх пакетів APT інсталятор викликає `sudo`; якщо залежності вже встановлено, адміністративні права не потрібні. Запуск від root заборонено.
- Для завантаження окремого скрипта потрібен `curl` (однорядкова команда з README встановлює його). Потрібен доступ до GitHub та репозиторіїв Ubuntu.
- Підтримувані архітектури випусків Starship: x86_64 та aarch64. Повна лабораторна перевірка проведена на x86_64.
- Найбезпечніша ціль — новий користувач без сторонніх `.zshrc` та `starship.toml`.

## Команди

```sh
sh ac-shell-setup.sh plan
sh ac-shell-setup.sh install
sh ac-shell-setup.sh install --latest
sh ac-shell-setup.sh install --set-default-shell
sh ac-shell-setup.sh verify
sh test-shell.sh
```

- `install` за замовчуванням ставить Starship **1.27.0** та зафіксовані ревізії Oh My Zsh і плагінів. За наявності `versions.tsv` повторна інсталяція використовує записану версію та не виконує downgrade.
- `--latest` під час першого встановлення знаходить **останній стабільний** Starship, поточні Git HEAD плагінів і зберігає повні SHA. Для вже налаштованого облікового запису режим **лише перевіряє**, а не оновлює.
- `--replace` дозволяє резервне копіювання і заміну існуючих `.zshrc`, `starship.toml` та локального виконуваного Starship з іншою версією. Існуючі Git-клони Oh My Zsh або плагінів з іншими ревізіями автоматично **не переписуються**.
- `--set-default-shell` явно запускає `chsh` (може знадобитися автентифікація). Для застосування потрібен новий вхід.
- `plan`, `verify`, `render-*` не встановлюють пакети й не змінюють конфігурацію.

## Керовані файли

```text
~/.zshrc
~/.oh-my-zsh/
~/.config/starship.toml
~/.local/bin/starship
~/.config/ac-shell/versions.tsv
```

SHA-256 архіву Starship перевіряється за контрольною сумою з **того самого** релізу upstream через HTTPS; це **не** незалежна перевірка підпису. Git-репозиторії завантажуються через HTTPS із фіксацією commit SHA. Для критичних production-систем потрібна окрема процедура перевірки підписаних тегів та довірених контрольних сум.

Скрипт відхиляє сторонні `STARSHIP_CONFIG` / `ZDOTDIR`, символьні посилання на керованих шляхах і сторонні файли конфігурації без дозволу. Перед заміною створюються резервні копії. Повний транзакційний rollback / uninstall **не реалізовано**. Не застосовуйте до важливих кастомізованих облікових записів адміністраторів без попередньої резервної копії.

## Безпечна перевірка

1. На ноутбуці виконайте `sh test-shell.sh` і `sh ac-shell-setup.sh plan`.
2. Для одноразового користувача `ac-shell-test` без попередньої інсталяції: `sh lab/run-local-user-lab.sh`. Він не змінює login shell або пакети хоста.
3. У QEMU/KVM від непривілейованого користувача хоста: `sh lab/ac-shell-vm-lab.sh prepare`, `start`, `test`, `status`. Подробиці: [Лабораторія](lab/README.md).
4. Лише після тестів розгортайте на іншій машині з зафіксованого релізу.

**Не повторюйте** локальний лабораторний сценарій на вже налаштованому `ac-shell-test`: він навмисно відмовить. VM-сценарій `test` також розрахований на чисту гостьову систему.

## Оновлення

`--latest` обирає версії **лише під час першого встановлення**. Фонових оновлень немає. Окрема команда `update`, тести сумісності й відкат — майбутні завдання. Звичайні безпекові оновлення Ubuntu виконуються стандартним пакетним менеджером.

## Поза межами проєкту

Не налаштовує root/system shell, bootstrap сервера, автоматичний deploy, оновлення ОС, міграцію на Devuan, інших користувачів, зовнішню систему облікових записів чи ідентифікації.
