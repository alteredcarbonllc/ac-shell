# Безопасность

**Язык:** [English](../../SECURITY.md) · [Українська](../uk/SECURITY.md) · Русский

- Установщик запускается от **непривилегированного целевого пользователя**; `sudo` используется только для отсутствующих зависимостей APT. Не запускайте сам установщик от root.
- `--latest` **не является** автоматическим фоновым обновлением: он один раз определяет версии upstream для нового пользователя и фиксирует их. Для production рекомендуются проверенные закреплённые релизы.
- Архив Starship проверяется по SHA-256 из того же GitHub-релиза через HTTPS, что **не равнозначно** независимой криптографической проверке автора. Git-ревизии Oh My Zsh и плагинов записываются и сверяются.
- Скачанный через `curl` скрипт — исполняемый код: изучите его и фиксируйте неизменяемый проверенный коммит или релиз на критичных хостах. Команда из README сначала скачивает файл, а не использует `curl | sh`.
- Существующие файлы настроек защищены, пока явно не указан `--replace`. Перед заменой сохраняются копии конфигураций и локального Starship. Полный транзакционный откат не реализован.
- **Никогда не коммитьте** частные dotfiles, SSH-ключи, токены, TOTP, файлы окружения, API-учётные данные, диски cloud-image или журналы, содержащие секреты.
- SSH лабораторной VM пробрасывается только на localhost; пользователь с passwordless sudo существует **только внутри одноразовой VM**. Не открывайте его SSH-порт в публичную сеть.
- Установщик не должен зависеть от identity, почты или VPN и не должен перезапускать production-сервисы.

При обнаружении уязвимости до появления специального приватного канала обратитесь к владельцу репозитория лично через используемый защищённый канал. Не выкладывайте учётные данные или инструкции по эксплуатации уязвимости в общедоступные Issues.
