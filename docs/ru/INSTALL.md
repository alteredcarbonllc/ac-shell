# Установка и эксплуатация

**Язык:** [English](../../INSTALL.md) · [Українська](../uk/INSTALL.md) · Русский

## Предварительные требования

- Ubuntu 22.04, 24.04 либо 26.04; полная установка с нуля проверена пока только на Ubuntu 24.04.
- Запускайте от **целевого пользователя, не root**. Для отсутствующих пакетов APT установщик вызывает `sudo`; если зависимости уже установлены, права администратора не требуются. Запуск от root запрещён.
- Для загрузки самостоятельного скрипта нужен `curl` (однострочная команда в README предварительно устанавливает его). Необходим доступ к GitHub и репозиториям Ubuntu.
- Поддерживаемые архитектуры релизного Starship: x86_64 и aarch64. Полные лабораторные проверки выполнены на x86_64.
- Самый безопасный вариант — новый пользователь без посторонних `.zshrc` и `starship.toml`.

## Команды

```sh
sh ac-shell-setup.sh plan
sh ac-shell-setup.sh install
sh ac-shell-setup.sh install --latest
sh ac-shell-setup.sh install --set-default-shell
sh ac-shell-setup.sh verify
sh test-shell.sh
```

- `install` по умолчанию устанавливает Starship **1.27.0** и закреплённые ревизии Oh My Zsh/плагинов. При наличии файла блокировки `versions.tsv` повторная установка использует записанную версию и не откатывает её.
- `--latest` при первой установке получает **последний стабильный** Starship и текущие Git HEAD плагинов, сохраняя полные SHA. Для уже настроенного пользователя режим **только проверяет**, а **не обновляет**.
- `--replace` разрешает резервное копирование и замену существующих `.zshrc`, `starship.toml` и локального исполняемого Starship другой версии. При этом Git-клоны Oh My Zsh/плагинов с несовпадающими ревизиями **не переписываются автоматически**.
- `--set-default-shell` явно вызывает `chsh`; может потребоваться подтверждение пользователя. Для применения надо войти заново.
- `plan`, `verify`, `render-*` не устанавливают пакеты и не меняют файлы настроек.

## Управляемые пути

```text
~/.zshrc
~/.oh-my-zsh/
~/.config/starship.toml
~/.local/bin/starship
~/.config/ac-shell/versions.tsv
```

SHA-256 архива Starship проверяется по контрольной сумме из **того же** upstream-релиза через HTTPS; это **не** независимая проверка подписи поставщика. Git-репозитории скачиваются по HTTPS с сохранением точных SHA коммитов. Для ответственных production-систем необходима отдельная процедура проверки подписанных тегов и доверенных хешей.

Скрипт отклоняет посторонние `STARSHIP_CONFIG` / `ZDOTDIR`, символические ссылки в управляемых путях и неразрешённые сторонние конфигурации. Перед заменой создаются резервные копии. Полный транзакционный rollback / uninstall **пока не реализован**. Не применяйте к важным кастомизированным аккаунтам администраторов без предварительной резервной копии.

## Безопасная последовательность тестов

1. На ноутбуке: `sh test-shell.sh` и `sh ac-shell-setup.sh plan`.
2. На одноразовом пользователе `ac-shell-test` без установленного окружения: `sh lab/run-local-user-lab.sh`. Этот сценарий не меняет login shell и пакеты хоста.
3. На QEMU/KVM от непривилегированного пользователя хоста: `sh lab/ac-shell-vm-lab.sh prepare`, `start`, `test`, `status`. Подробнее: [Лаборатория](lab/README.md).
4. Только после проверки устанавливайте на другую машину из закреплённого релиза.

**Не повторяйте** локальный лабораторный сценарий для уже настроенного `ac-shell-test`: он намеренно откажется. VM-сценарий `test` также предполагает чистую гостевую систему.

## Обновления

`--latest` выбирает версии **только при первом развёртывании**. Фоновых обновлений нет. Отдельная команда `update`, тесты совместимости и откат — будущие задачи. Обычные обновления безопасности Ubuntu выполняются через штатный пакетный менеджер.

## Вне области проекта

Не занимается root/system shell, серверным bootstrap, автоматическим deploy, обновлениями ОС, миграцией на Devuan, окружениями чужих пользователей и внешней системой идентификации/учётных записей.
